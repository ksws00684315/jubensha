# ADR 0002：状态版本化

## 背景

游戏状态快照会随着功能演进而改变。没有版本号时，读取代码只能从字段缺失情况猜测旧格式，兼容逻辑容易散落在加载和业务处理路径中。

## 决策

`GameState` 保存 `stateVersion`，新状态写入当前版本。读取快照时先按版本逐步迁移，再用当前 Zod schema 校验；无版本号的旧快照按 v0 处理。现有兼容字段补齐与清理逻辑保持幂等，并对所有版本执行，以保留旧加载行为。

## 备选方案

- 每次格式变化都清空旧对局：会丢失正在进行的游戏。
- 在各调用点按字段是否存在分支：迁移规则会重复且难以完整验证。
- 只给数据库记录加版本而不验证快照：无法及时拒绝结构损坏的数据。

## 后果

格式演进有明确入口和可测试的迁移链，损坏或不支持的快照会在边界处暴露。每次更改状态格式都需要添加迁移及旧版本样本测试；迁移必须保持已存在快照的业务语义。
