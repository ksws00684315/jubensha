# ADR 0003：事件快照原子写

## 背景

游戏事件用于恢复和观察流程，快照用于快速加载当前状态。若事件写入成功而快照更新失败，或反过来，事件流与可读状态就会互相矛盾。

## 决策

追加事件时若同时提供状态快照，将 `game_events` 插入与 `games` 状态、阶段和轮次更新放进同一个数据库事务。事务提交成功后才发布事件；没有快照的控制消息不作为领域事件发布。

## 备选方案

- 先写事件再更新快照：进程在两次写入之间退出会留下不一致状态。
- 先更新快照再写事件：失败时快照会领先于事件流。
- 依赖进程内回滚或补偿任务：跨越崩溃边界时无法保证及时且唯一地完成补偿。

## 后果

事件与快照在数据库中一起提交或一起回滚，发布方不会提前通知尚未提交的数据。事务内写入增加少量数据库事务开销；发布仍发生在提交之后，消费者必须以持久化事件记录作为事实来源。
