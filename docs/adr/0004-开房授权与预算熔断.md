# ADR 0004：开房授权与预算熔断

## 背景

生产环境开放创建含 AI 座位的房间会增加滥用风险；模型调用也可能因流量或异常循环产生不可预期的日用量。部署者需要明确可配置的开房权限，并能设置调用预算上限。

## 决策

按已批准的策略，开发环境默认允许开房，生产环境默认要求管理员身份；另提供 `invite` 模式，由服务端常量时间比较邀请码。`LLM_DAILY_TOKEN_BUDGET` 未设置或为 0 时关闭预算限制；设置正数后，`chat`、`chatStream` 和 `embedTexts` 在调用模型前检查服务器本地日期的累计用量，达到预算则抛出专用预算错误，由引擎走既有降级路径。

## 备选方案

- 所有环境一律开放：生产入口缺少默认保护。
- 所有环境一律管理员开房：开发和受邀部署缺少轻量选项。
- 只在 UI 限制开房或只在模型调用后告警：客户端可绕过 UI，事后告警也不能阻止继续产生费用。
- 固定硬编码预算：无法适配不同部署方的规模和成本边界。

## 后果

生产默认更安全，同时保留开发开放和邀请码部署方式；预算在模型请求发出前拦截，并由设置值控制。预算依赖用量记录和服务器本地日界线，短缓存可能让并发请求在阈值附近出现有限超额；预算关闭时保持原有调用路径。
