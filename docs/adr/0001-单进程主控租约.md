# ADR 0001：单进程主控租约

## 背景

游戏引擎按需恢复时，多个应用实例可能同时加载同一局并推进状态，造成重复事件或重复 AI 操作。部署允许多个 Web 实例访问同一个数据库，因此需要数据库可见的单写者协调。

## 决策

每局在数据库保存 `ownerId` 和 `leaseUntil`。实例通过条件更新取得过期或空闲租约；持有者定期续租，续租失败时停止计时器、取消活动操作并移除本地引擎。进程收到 `SIGTERM` 时主动交还租约。租约不能取得的实例不推进该局。

## 备选方案

- 使用进程内互斥锁：跨进程不可见，不能阻止另一实例写入。
- 使用 Redis 分布式锁：需要新增基础设施和运维依赖。
- 允许多个引擎并发写入，再用事件冲突检测补救：无法可靠撤销已经发生的外部调用和副作用。

## 后果

租约状态与游戏数据共用数据库，不需要新增服务；数据库短暂不可用时，引擎需保守地停止写入。租约到期提供崩溃恢复，正常退出则可更快交接。此模型约束的是同一局的引擎写者，不是整个应用只能运行一个 Web 实例。
