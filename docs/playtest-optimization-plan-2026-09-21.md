# 试玩问题系统优化与跨剧本验证计划

> 制定日期：2026-09-21  
> 依据：[《第七封贺卡》真人实测报告](../.workbuddy/audit/2026-09-20-playtest-diqifengheka.md)  
> 实测对局：房间 `LWYUR`，gameId `cmu9ydiac0007s8tk44yu2nri`，陈曼真人、其余四座 AI、AI 主持。

## 一、目标与实施顺序

本轮解决《第七封贺卡》实测暴露的系统性问题，并通过不同剧本验证改动没有只适配单一内容。

实施顺序：

1. **P0：修复搜证结算竞态，统一主持保证公开语义。**
2. **P1：消除重复回答和重复提问，压缩 AI 发言。**
3. **P1：强化真凶辩解，增加可复用的轻量互动节点。**
4. **P2：完善证据化投票、来源展示和模型能力诊断。**
5. **验证：先同本回归，再进行跨剧本迁移测试。**

引擎优化对全部剧本生效；内容调整先落到《第七封贺卡》。历史游戏继续读取局内剧本快照，不切换到新版正文。

## 二、核心实现

### 1. 搜证与主持兜底

将搜证结束顺序固定为：

`分配线索 → 玩家公开/私藏决定 → 主持检查截止材料 → 幂等补发 → 进入讨论`

- `dispatchClues` 只负责分配线索，不立即执行主持补发。
- 新增唯一的 `finalizeSearchRound`，仅在全部 `pendingPublish` 清空后执行保证公开和阶段切换。
- 保留加载旧快照时清理“已经公开但仍在待决策队列中”线索的恢复逻辑。
- 主持补发继续使用 `hostHandouts` 保证重启、重复 tick 和重复请求下只发生一次。
- 玩家持有的保证材料在截止轮之前可以私藏；到截止轮结束时才由主持公开。
- 若线索在当前轮结束时必定公开，界面明确显示“暂时私藏，本轮结束由主持公开”。
- 每次连续补发最多展示两张线索，其余作为同批次后续事件交付，避免事件流瞬间涌入大量卡片。

校验规则：

- `manual_public` 线索的 `deadlineRound` 等于首次可获取轮次时，产生“没有有效私藏窗口”警告。
- 正式种子发布流程把该警告视为内容阻断；作者必须改成 `auto_public`、延后截止轮次或取消保证。
- `keep_private`、不可达前置、循环依赖和重复保证继续作为确定性错误。

《第七封贺卡》内容调整：

- 药盒和急救记录作为第一轮确定公开的基础事实。
- 点单、换酒便签和分别陈述允许至少跨一轮保留，再于最终截止前兜底。
- 第二轮只保证定罪必需的风险认知与受益材料，不把所有辅助材料同时补发。
- 成绩底单等辅助材料保留正常搜证路径；第七封贺卡必须在情感互动节点前可见。

### 2. 质询、插话与讨论去重

新增问题标识：

```ts
type PendingAnswer = {
  questionId: string;
  fromSeat: number;
  toSeat: number;
  question: string;
  evidenceIds?: string[];
  forced?: boolean;
};

type QuestionFingerprint = {
  toSeat: number;
  evidenceKey: string;
  normalizedText: string;
};
```

处理规则：

- `submitQuestion` 生成 `questionId`，问题事件、待回答状态和回答事件共用该 ID。
- 插话任务在生成前和提交前检查：同一提问者已经向该目标建立 `pendingAnswer` 时，取消插话。
- 一次问题只允许一个正式回答事件；迟到插话、迟到修订和旧 generation 全部丢弃。
- 问题去重范围从“同一提问者”扩大到当前轮全场。
- 同一目标和相同证据集合直接视为重复。
- 未提供证据时，对规范化问题文本做中文二元组相似度比较，阈值为 `0.72`。
- 引用了上次问题之后才公开的新证据时，允许继续追问。
- AI 提问提示注入全场本轮问题目录，不再只注入自己问过的问题。
- 真人提问界面增加可选公开证据标签，帮助保存来源并提高去重准确度。

### 3. AI 发言长度与信息增量

扩展私有行动计划：

```ts
type PlayerActionPlan = {
  objectiveId: string | null;
  targetSeat: number | null;
  discloseClueIds: string[];
  holdClueIds: string[];
  focusEvidenceIds: string[];
  claimSummary: string | null;
  defenseHookId: string | null;
  nextAction: "state" | "ask" | "defend" | "probe" | "exchange" | "wait";
};
```

- `claimSummary` 限制为 80 字，只描述本回合准备新增的主张。
- 正式发言事件保存 `claimSummary`、`focusEvidenceIds` 和关联的 `questionId`。
- 计划提示注入本轮已有 claim 目录，要求每次只贡献一个新主张、反驳或问题。
- 普通陈述目标长度调整为 40–120 字；强制回答为 40–140 字。
- 质量审核发现“无新证据且主张重复”时最多修订一次；仍重复则改为简短附议或跳过。
- 保留现有流式字符循环熔断；它处理文本内部循环，新逻辑处理不同角色之间的语义复述。
- 前端在 AI 发言下展示引用的公开线索；没有引用时标为“角色陈述”。

### 4. 真凶辩解生命周期

现有 `brokenByPublicClueIds` 采用“任意一张公开即失效”，不能表达多张材料共同击破。新增兼容结构：

```ts
type DefenseBreakCondition = {
  allPublicClueIds?: string[];
  anyPublicClueIds?: string[];
};

type DefenseHook = {
  id: string;
  claim: string;
  basis: string;
  brokenByPublicClueIds?: string[];
  brokenWhen?: DefenseBreakCondition;
};
```

- 新剧本优先使用 `brokenWhen`；旧字段维持“任一材料公开即失效”的原语义。
- `allPublicClueIds` 全部公开，或 `anyPublicClueIds` 任一公开时，辩解失效。
- 真凶行动计划必须选择一条仍成立的 `defenseHookId`。
- 上一回合辩解仍成立时默认继续使用，避免每轮随机换口径。
- 生成和质量审核禁止角色主动承认会直接推翻当前辩解的事实。
- 辩解失效后允许承认有限事实并切换下一条，诊断记录切换原因。

《第七封贺卡》的赵凯至少保留两层防守：

1. 早期质疑旧手机操作者，以及自己是否听清用药信息；需要搜索记录和两份独立陈述共同击破。
2. 中期承认安排酒水，但否认知情后持续施压；需要点单、时间线和促酒证词共同击破。

第一轮结束前至少一条辩解仍可成立；关键证据全部公开后，两条均应失效。

### 5. 可复用的轻量互动节点

在 `flow` 增加可选配置：

```ts
type InteractionBeat = {
  id: string;
  round: number;
  timing: "after_discussion";
  characterId: string;
  prompt: string;
  choices: Array<{
    id: string;
    label: string;
    recap: string;
  }>;
  defaultChoiceId: string;
  visibility: "public" | "private";
};
```

运行状态增加：

```ts
pendingInteraction?: {
  beatId: string;
  seatIndex: number;
};

interactionChoices?: Record<string, {
  seatIndex: number;
  choiceId: string;
  round: number;
}>;
```

- 节点在指定讨论轮结束后、进入下一阶段前依次执行，不新增游戏阶段。
- 真人通过按钮选择；AI 根据自身角色视角进行一次结构化选择。
- 超时或生成失败使用 `defaultChoiceId`，保证流程不中断。
- 对应角色未入座时记录跳过，不阻塞游戏。
- 选择写入 `interaction` 事件，刷新和重启后保持一致。
- 互动结果不改变真凶判定或结局分支，但进入主持复盘和结构化揭晓的“角色抉择”区域。

《第七封贺卡》配置两个节点：

- 林素芬：接受迟到的道歉、拒绝原谅、暂不回应。
- 陈曼：说出自己等待的话、继续保守秘密、保持沉默。

终局必须按玩家实际选择回收，不再固定代述角色态度。

### 6. 证据化投票

玩家摘要接口新增：

```ts
publicEvidence: Array<{
  id: string;
  name: string;
}>;
```

- 真人投票面板展示公开证据多选标签。
- 存在公开证据时，投票至少选择一张；没有公开材料时允许无证据投票。
- 服务端过滤不存在、私密和未来材料；过滤后为空则拒绝提交。
- AI 首次生成非法引用时重试一次；仍失败时使用合法公开材料生成保守理由。
- `GameState.votes` 和投票事件保存 `evidenceIds`，历史 Vote 记录保持兼容。
- 终局统计能够解释每票引用了哪些材料。

### 7. 模型协议诊断

保留已有 system 消息自动合并重试，增加持久化检测：

```ts
ModelBinding.detectedSystemSupport?: boolean;
ModelBinding.capabilityDetectedAt?: DateTime;
UsageLog.fallbackReason?: string;
```

- 管理员配置继续表示期望能力；运行检测结果单独保存，不静默覆盖人工配置。
- 已检测到不支持 system 的绑定在服务重启后直接使用兼容格式，避免每次重启后的首次失败。
- 流式首试失败但兼容重试成功时，记录为一次成功逻辑调用，`retryCount=1`、`fallbackReason=system_role_rejected`。
- 只有兼容重试也失败时才生成 `ok=false` 的最终日志。
- 设置页显示配置能力、检测能力、实际消息模式和最后检测时间。

## 三、兼容、数据与内容修订

- `interactionBeats`、`pendingInteraction`、`interactionChoices` 和行动计划新字段均为可选；旧快照加载时补空值。
- 历史 `brokenByPublicClueIds` 保持原语义，正式种子逐步迁移到 `brokenWhen`。
- 历史投票继续展示；证据必选只约束新版动作提交。
- 修正《第七封贺卡》真相时间线 20:58 节点，明确主语为“林素芬回包厢提醒郑国栋正在服用头孢”。
- 检查终局时间线标题、角色和正文的换行拼接。
- 更新 V2 JSON Schema、生成提示、校验器和正式剧本清单。
- 其他正式剧本只生成新增校验问题清单，本批不自动改写其正文。

数据库和内容发布顺序：

1. 备份正式数据库中的 Script 和相关配置记录。
2. 部署增量数据库迁移和兼容读取。
3. 运行剧本同步 dry-run，检查新增、更新、失败及 hash。
4. 只同步通过校验的《第七封贺卡》内容。
5. 历史 Game 快照不回填新版正文。

## 四、自动化测试

必须覆盖：

- 玩家搜到截止保证材料后选择公开、暂时私藏、超时和重启恢复，均能结束搜证且只公开一次。
- 已公开线索残留在 `pendingPublish` 的旧存档加载后自动恢复。
- 正式提问建立后，同目标插话任务在生成前和提交前都会取消。
- 不同 AI 使用相同目标和证据组合时，第二个问题被拒绝；新增证据后允许继续追问。
- `questionId` 把问题与唯一回答对应，迟到回答不能提交。
- 行动计划只能引用合法可见材料和仍成立的辩解。
- `allPublicClueIds` 未集齐时辩解仍成立，集齐后失效；旧字段保持兼容。
- 互动节点覆盖真人选择、AI 选择、超时默认、角色缺席和重启恢复。
- 真人投票无合法证据时被拒绝，合法选择进入状态和事件。
- system 角色被拒绝后兼容重试成功，只产生一条最终成功日志，并能在重启后复用检测结果。
- 全量 Vitest、TypeScript、ESLint、Schema 生成、正式种子校验和生产构建通过。

## 五、真人与 AI 混合复测

### 1. 同本回归：《第七封贺卡》

配置：陈曼真人，其余四座 AI，AI 主持。

重点验证：

- 搜证不再卡死，主持补发发生在公开决策之后。
- 一次质询只出现一次赵凯回答。
- 同轮没有无新证据的重复问题。
- AI 正式发言中至少 80% 带来新 claim、新证据或新问题。
- 真人和 AI 投票都能定位到合法公开证据。
- 赵凯第一轮仍有一条可核验辩解，终局前能被公开材料击破。
- 林素芬和陈曼完成显式情感选择，复盘准确引用实际结果。
- 终局保持主持复盘 → 唯一揭晓 → `ENDED`。

再追加赵凯真人视角复测，确认真人可以使用辩解，系统不会替真人自动认罪。

### 2. 跨剧本验证：《云澜山庄的雪夜》

配置：周伯真人，苏晚及其余角色由 AI 扮演，AI 主持。

选择理由：

- 同为五人、两轮搜证和两轮讨论，便于控制流程变量。
- 配置了多项主持保证材料，能够验证新的补发时机。
- AI 真凶苏晚拥有两条辩解钩子，可以验证辩解生命周期。
- 周伯掌握模糊目击并需要保护账本秘密，能够检验事实、角色陈述和推测的边界。
- 剧本开放私聊，可以覆盖《第七封贺卡》实测中没有自然发生的私聊路径。

重点验证：

- 主持保证材料在玩家公开决策完成后才补发，且只补发一次。
- 私藏至少拥有一轮有效窗口，界面承诺与实际规则一致。
- 同一问题只产生一次回答，无新证据时不重复质询同一角色。
- 苏晚能在证据不足时维持合理辩解，击破材料齐全后才调整说法。
- 周伯的模糊目击不会被 AI 当成确定事实。
- AI 发言能区分公开材料、角色陈述和推断。
- 私聊遵守双方信息边界，并具有实际策略用途。
- 真人与 AI 投票均引用合法公开证据。
- 终局顺序、刷新恢复、调用成本和延迟保持稳定。

《云澜山庄》不为本次验证临时增加情感互动节点；该能力继续由《第七封贺卡》验收。

### 3. 成本基线

《第七封贺卡》当前基线：69 次逻辑调用、约 360,327 输入 token、缓存命中率约 50.8%。

- 同配置连续运行三次，以中位数评估。
- 逻辑调用数和输入 token 中位数不得比基线增加超过 10%。
- 常规阶段主持调用继续为零。
- 协议兼容首试不再计为最终失败。
- 记录规划、审核、修订、互动选择和重试的独立成本。

## 七、完成条件

- 搜证竞态、重复回答和重复质询均有确定性回归测试且不再复现。
- 玩家能理解保证公开材料的真实规则，并拥有有效的信息选择空间。
- AI 发言明显缩短，重复内容不再主导讨论。
- 真凶辩解在证据不足时成立，在材料齐全后能够被可靠击破。
- 情感选择由玩家实际作出并进入复盘，不由结局文本代替玩家决定。
- 真人和 AI 投票均可追溯合法公开证据。
- 模型协议兼容在重启后稳定，不制造虚假的最终失败统计。
- 两个不同剧本均通过真人与 AI 混合复测。
- 全量检查、迁移、构建、PM2 运行和数据库内容同步全部完成。

本轮不引入多结局分支、通用技能扩展、服务端消息撤回或新的游戏阶段。轻量互动节点只记录角色选择并影响复盘文本。
